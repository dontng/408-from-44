## 01｜2024-13：伪指令、汇编指令、机器指令、微指令

**首次作答：C；正确答案：B；当前状态：`explained`。**

### 真正要解决的问题

不能先猜“你不懂伪指令”或“你不懂微指令”。选择 C 只证明：四种“指令”还没有按照**谁产生、谁读取、谁执行**排在同一条链上。本题需要建立的是程序表示层次，不是背四个定义。

### 最小机制

```text
程序员写下的内容

伪指令 ──汇编器展开──┐
                      ├──→ 机器指令：ISA 规定的二进制编码
汇编指令──汇编器翻译──┘             │ CPU 取指、译码
                                     ▼
                         微指令：微程序控制器内部的控制步骤
                                     │
                                     ▼
                                  控制信号
```

- **伪指令**没有可供 CPU 取指的机器编码；它是汇编器提供的方便写法，汇编时被展开。
- **汇编指令**是机器指令的文本助记形式，仍需汇编器翻译。CPU 不直接读取 `ADD R1,R2` 这样的文本。
- **机器指令**是 ISA 对程序员公开的二进制编码，CPU 从存储器取出并译码执行。
- **微指令**位于采用微程序控制的 CPU 内部，由控制存储器给出，用来产生一组控制信号。它不属于程序员编写的 ISA 程序。

408 在本题中把“CPU 内部能够直接处理”作为口径，因此机器指令和微指令成立。硬布线控制器不使用微程序，但这不可能使伪指令或汇编文本变成 CPU 直接执行的对象。

### 逐项裁决

| 项 | 裁决 | 原因 |
| --- | --- | --- |
| I 伪指令 | × | 汇编器展开，CPU 看不到 |
| II 微指令 | ✓ | 微程序控制器内部直接执行 |
| III 机器指令 | ✓ | CPU 取指、译码和执行的 ISA 编码 |
| IV 汇编指令 | × | 汇编器翻译，CPU 不执行文本助记符 |

所以选 **B：仅 II、III**。C 的诱因是把“汇编语言已经很底层”偷换成“CPU 可以直接执行”。

### 最小验证

不要再问原选项。请给下面四个对象分别填写“直接消费者”：

| 对象 | 汇编器 | CPU 指令译码器 | 微程序控制器 |
| --- | --- | --- | --- |
| `li` 伪指令 |  |  |  |
| `add` 汇编助记符 |  |  |  |
| 二进制 `ADD` 机器指令 |  |  |  |
| 一条控制存储器中的控制字 |  |  |  |

<details>
<summary>核对</summary>

前两项先由汇编器处理；机器指令由 CPU 指令译码器读取；控制字作为微指令由微程序控制器读取。关键不是名称里有没有“指令”，而是谁真正消费它。

</details>

## 02｜2024-16：Cache—主存与主存—外存不能机械类比

**首次作答：不会；正确答案：D；当前状态：`explained`。**

### 真正要解决的问题

题目不是让人背两层存储系统的四组结论，而是在四个不同维度上比较：**交换单位、替换执行者、写策略、放置位置**。如果把四个维度混成“上层快、下层慢”，就无法判断选项。

### 最小机制

| 维度 | Cache—主存 | 主存—外存（虚拟存储） |
| --- | --- | --- |
| 交换单位 | 主存块 / Cache 行 | 页 |
| 缺失后的替换 | 硬件必须快速完成 | 操作系统参与选择和换入换出 |
| 修改后的写回 | 可采用写回法 | 通常写回；脏页换出时才写外存 |
| 一个下层块放到哪里 | 可直接、组相联或全相联 | 虚拟页可进入任意空闲页框，等价于全相联放置 |

最后一行是本题的刀口。若虚拟页只能按直接映射进入某个固定页框，那个页框被占用时，即使别处大量空闲也无法装入，虚拟存储失去灵活调页的能力。页表正是用来记录“这个虚拟页当前落在哪个页框”。

### 逐项裁决

- A 正确：交换单位分别是块和页。
- B 正确：Cache 的速度要求替换由硬件完成；页面置换由操作系统参与完成。
- C 正确：两层都可以避免每次修改立即向更慢层写入，而在替换时写回。
- D 错误：Cache 可以直接映射；虚拟页通常可放入任意页框，不是直接映射。

所以选 **D**。

### 最小验证

物理内存有 4 个页框，当前只有页框 0 被占用。若虚拟页 4 按“页号 mod 4”直接映射，它只能进入哪个页框？此时另外 3 个空闲页框能否被利用？

<details>
<summary>核对</summary>

只能映射页框 0，另外 3 个空闲页框也无法使用。这正说明主存—外存层次不能通常采用直接映射。

</details>

## 03｜2024-17：TLB 标记位从哪段地址里切

**首次作答：不会；正确答案：C；当前状态：`explained`。**

### 真正要解决的问题

本题不是公式记忆，而是先确定：TLB 用什么去查找页表项。答案是**虚拟页号**。物理地址位数会影响页框号，却不参与本题的 TLB 标记匹配。

### 最小机制

虚拟地址 32 位，页大小 `1 KB = 2^10 B`：

```text
虚拟地址 32 位
┌──────────────虚拟页号 22 位──────────────┬─页内偏移 10 位─┐
```

TLB 有 32 项、4 路组相联：

```text
组数 = 32 / 4 = 8 = 2^3

虚拟页号 22 位
┌────────────标记 19 位────────────┬─组号 3 位─┐
```

因此最少需要：

```text
32 - 10 - 3 = 19 位
```

题目说“至少”，是因为真实 TLB 表项还可能保存有效位、权限、地址空间标识等；但这些不属于本题所问的标记匹配位。30 位主存地址在这里是干扰条件。

### 逐项裁决

只有 **C：19** 符合地址切分。17、18、20 都来自错误地多减或少减一段字段。

### 最小验证

保持 32 位虚拟地址和 1 KB 页不变，把 TLB 改成 32 项、全相联。标记至少多少位？再改成 32 项、直接映射呢？

<details>
<summary>核对</summary>

全相联只有 1 组，没有组号，标记为完整虚拟页号 22 位；直接映射有 32 组，组号 5 位，标记为 `22-5=17` 位。

</details>

## 04｜2024-18：MMU 管翻译，Cache 管数据命中

**首次作答：D；正确答案：B；当前状态：`explained`。**

### 真正要解决的问题

选择 D 不能直接证明你“不懂 TLB”。更可靠的判断是：地址翻译与 Cache 访问的责任边界尚未排清。本题只需建立一条访问路径。

### 最小机制

在 408 的典型模型中：

```text
虚拟地址
   │
   ▼
MMU：查 TLB / 查页表 / 检查权限
   │
   ├── TLB 缺失：没有找到近期页表项，继续查页表
   ├── 页面缺失：页表表明页面不在主存，触发缺页异常
   └── 访问越权：权限位不允许本次访问
   │
   ▼
物理地址
   │
   ▼
Cache：判断对应数据块是否命中
```

Cache 缺失不是虚拟地址无法翻译，而是需要的数据块当前不在 Cache。它由 Cache 访问逻辑检测，不是 MMU 地址转换过程检测的事件。

### 逐项裁决

- A 访问越权：MMU 检查页表或 TLB 中的权限信息。
- B Cache 缺失：不属于 MMU 地址转换过程。
- C 页面缺失：地址翻译发现页面不在主存。
- D TLB 缺失：MMU 查询 TLB 时直接产生。

所以选 **B**。

### 最小验证

若某虚拟地址成功翻译成物理地址，但对应主存块不在 Cache，这次访问能否同时出现“地址翻译成功”和“Cache 缺失”？

<details>
<summary>核对</summary>

可以。二者属于连续但不同的机制；这正是不能把 Cache 缺失归给 MMU 的原因。

</details>

## 05｜2024-19：转发解决“来得及送”，不能让数据提前产生

**首次作答：D；正确答案：C；当前状态：`explained`。**

### 真正要解决的问题

本题的关键不是看到“所有”就条件反射排除，而是必须拥有一个能击穿“所有数据冒险均可转发”的反例。经典反例是紧邻的 `load-use`。

### 最小机制

五段流水线：

```text
IF → ID/取数 → EX → MEM → WB
```

- 普通 ALU 指令在 **EX 结束**时得到结果，下一条指令进入 EX 时通常可以通过转发拿到。
- `load` 要到 **MEM 结束**才从存储器得到数据；紧邻的下一条指令在同一周期已经需要进入 EX，数据产生得太晚。

```text
周期       1    2    3    4    5
load       IF   ID   EX   MEM  WB
use             IF   ID   EX   MEM
                         ↑需要   ↑才产生
```

转发只能缩短“结果已产生但尚未写回”的等待，不能把尚未产生的数据提前。因此紧邻 `load-use` 仍需插入一个气泡。

### 逐项裁决

- A 正确：相邻指令存在 RAW 等操作数相关时可能产生数据冒险。
- B 正确：插入气泡可以等待数据产生。
- C 错误：紧邻 `load-use` 不能仅靠转发消除。
- D 正确：重新调度独立指令，或插入足够的 `nop`，都可以把使用推迟到数据可用之后。

所以选 **C**。你选择 D 可能来自对“调整顺序是否总能找到独立指令”的怀疑；但 D 还允许插入 `nop`，因此总能用等待解决，代价只是性能。

### 最小验证

在 `load` 和使用其结果的指令之间插入一条与二者无关的 ALU 指令。重新画三条指令的 EX/MEM 时刻：此时还需要气泡吗？

<details>
<summary>核对</summary>

典型五段流水线配合转发时不再需要额外气泡。无关指令把使用者的 EX 推迟一周期，`load` 的数据已经可以从 MEM/WB 路径转发。

</details>

## 06｜2024-20：峰值带宽与一笔突发事务的平均速率

**首次作答：不会；正确答案：B；当前状态：`explained`。**

### 真正要解决的问题

题目故意同时给出“总线物理能力”和“一笔突发事务的时序”。必须先确定它问的是哪一个量。题干明确问**总线带宽（最大数据传输率）**，因此取连续传送数据时的峰值，不把地址阶段和等待阶段摊入。

### 最小机制

```text
频率：420 MHz
每周期传送：2 次
每次宽度：64 bit = 8 B

峰值带宽
= 420×10^6 周期/s × 2 次/周期 × 8 B/次
= 6.72×10^9 B/s
= 6.72 GB/s
```

第 4—7 周期连续传 8 次数据，恰好也是每周期 2 次，验证了上述物理峰值。

为什么 A 是 3.84 GB/s？

```text
一笔突发共传 8×8 B = 64 B
从第 1 周期开始到第 7 周期结束，共占 7 个周期

64 B ÷ (7 / 420 MHz) = 3.84 GB/s
```

这是**把整笔事务开销摊进去后的平均有效速率**，不是题目所问的总线峰值。短解析若只说“时序是干扰”，会丢掉 A 为什么存在；把两个量同时分清，题目才真正结束。

### 逐项裁决

- A 3.84 GB/s：单次给定突发事务的平均有效速率。
- B 6.72 GB/s：总线连续传输数据时的最大带宽。
- C 30.72 GB/s、D 53.76 GB/s：混淆单位或重复使用条件；其中 53.76 是 `Gb/s`，不是 `GB/s`。

所以选 **B**。

### 最小验证

若题目最后一句改成“按上述一次突发事务计算，从发出地址到最后一次数据传送完成的平均数据传输率”，应选哪个数？

<details>
<summary>核对</summary>

应为 3.84 GB/s。这个改问法用来检验是否真正区分了峰值与事务平均值。

</details>

## 07｜2024-21：响应优先级与处理优先级不是一回事

**首次作答：不会；正确答案：A；当前状态：`explained`。**

### 真正要解决的问题

本题把两个维度交叉在一起：谁完成动作（硬件/软件），动作发生在哪个阶段（响应/处理）。中断屏蔽字又容易被笼统地叫作“调整优先级”，必须进一步区分响应优先级和处理优先级。

### 最小机制

```text
多个请求同时到来
      │
      ▼
硬件排队/判优：决定先响应谁        ← 响应优先级
      │
      ▼
中断响应：保存断点、PSW，转入入口  ← 硬件
      │
      ▼
中断服务程序：保存通用寄存器、
设置屏蔽字、处理设备               ← 软件
```

- **响应优先级**决定多个请求同时存在时先接受谁，通常由硬件排队与判优机制决定。
- **中断屏蔽字**决定当前处理过程中允许哪些中断再次进入，从而改变实际处理次序，即处理优先级。
- 单重中断不允许处理过程中再次响应其他可屏蔽中断，所以服务期间保持关中断。

### 逐项裁决

- A 错误：屏蔽字不负责确定硬件响应优先级。
- B 正确：断点和程序状态字在中断响应阶段由硬件保存。
- C 正确：通用寄存器保存和新屏蔽字设置由中断服务程序完成。
- D 正确：单重中断的处理阶段保持关中断。

所以选 **A**。

### 最小验证

设备 A 的硬件响应优先级高于 B，但正在处理 A 时，新的屏蔽字允许 B、屏蔽 A。此后 A、B 同时请求，当前处理结束后的实际处理次序能否与固定硬件响应次序不同？

<details>
<summary>核对</summary>

可以。屏蔽字不改写硬件本身的响应优先级，却能通过“谁当前被允许进入”改变实际处理次序。

</details>

## 08｜2024-22：DMA 控制器负责搬运，不是数据的终点

**首次作答：不会；正确答案：C；当前状态：`explained`。**

### 真正要解决的问题

“DMA 控制器控制传输”容易被误听成“数据传到 DMA 控制器”。控制者和数据通路的两个端点不是一回事。

### 最小机制

程序查询或中断驱动 I/O 中，CPU 可能亲自读设备寄存器、再写主存。DMA 的目的正是取消这次逐字搬运：

```text
CPU：提前配置源地址、目的地址、长度
                 │
                 ▼
设备接口 ═════ 数据 ═════ 主存
                 ▲
            DMA 控制器产生地址、
            读写控制并申请总线
```

DMA 控制器可以包含少量数据缓冲寄存器，但从系统功能看，所控制的数据传输通路连接的是设备接口和主存；CPU 只负责配置与完成后的处理。

### 逐项裁决

- A CPU—主存：这是 CPU 正常访存通路，不是设备数据的两个端点。
- B CPU—DMA 控制器：CPU 配置控制器，不逐字接收数据。
- C 设备接口—主存：DMA 的直接数据传送路径。
- D 设备接口—DMA 控制器：只截取了局部控制器连接，漏掉最终主存端点。

所以选 **C**。

### 最小验证

若 DMA 每传一个字都必须先交给 CPU 通用寄存器，再由 CPU 写入主存，它还消除了中断方式中的哪项 CPU 工作？

<details>
<summary>核对</summary>

没有消除逐字搬运，只是换了通知方式。这与 DMA 释放 CPU 的目的矛盾，因此数据不能以 CPU 为必经中转站。

</details>

## 09｜2024-23：事件发生时与处理程序开始时

**首次作答：不会；正确答案：A；当前状态：`explained`。**

### 真正要解决的问题

本题的陷阱只有一个时间差，却横跨中断、异常、系统调用：事件可以在用户程序执行时发生；CPU 接受事件并进入内核后，处理程序才开始运行。把两者压成同一时刻，就会认为 A 正确。

### 最小机制

```text
用户程序正在用户态运行
        │
        ├── 外设提出中断请求
        ├── 当前指令产生异常
        └── 程序主动执行系统调用/陷入
        │
        ▼
硬件保存必要状态、切换到内核入口
        │
        ▼
中断/异常/系统调用服务程序在内核态执行
```

所以，“发生时”描述事件来源时刻，CPU 可能仍是用户态；“处理程序开始执行时”才必然已经进入内核态。

### 逐项裁决

- A 错误：中断或异常可以在 CPU 执行用户程序时发生。
- B 正确：系统调用号对应内核提供的服务处理入口。
- C 正确：中断处理程序开始时已经进入内核态。
- D 正确：系统增加新类型设备时，驱动需要为相应中断建立处理入口。

所以选 **A**。

### 最小验证

程序在用户态执行除法指令，除数为 0。请分别判断“除零异常刚被当前指令触发”和“异常处理程序第一条指令开始执行”两个时刻的 CPU 模式。

<details>
<summary>核对</summary>

异常由用户态指令触发；进入异常处理程序前，硬件完成模式切换，处理程序第一条指令在内核态执行。

</details>

## 10｜2024-24：终止当前进程，不等于必须终止其子进程

**首次作答：A；正确答案：A；当前状态：`explained`。**

### 真正要解决的问题

首次选对不能直接视为掌握。本题在问操作系统撤销一个进程时，哪些动作属于该进程自身资源的必然清理，哪些属于进程关系策略。

### 最小机制

在 408 的抽象模型中，终止进程需要撤销该进程本身：

- 释放其占用或持有的设备；
- 回收分配给它的内存；
- 移出进程管理结构并释放 PCB；
- 保存或传递必要的退出信息。

子进程不是父进程拥有的一块内存或设备。父进程退出后，系统可以让子进程继续运行，并重新指定其父进程；是否级联终止取决于系统策略，因此不是必然动作。

现实系统里还存在更细的生命周期。例如 Unix 子进程退出后可能暂时保留僵尸记录，等待父进程读取退出状态。2024-24采用的是408“撤销进程并回收资源”的抽象，不考察这项实现细节，不能让现实例外遮住本题的分类轴。

### 逐项裁决

- A 终止子进程：不一定。
- B 回收进程占用的设备：属于自身资源清理。
- C 释放进程控制块：属于撤销进程。
- D 回收为进程分配的内存：属于自身资源清理。

所以选 **A**。

### 最小验证

父进程 P 创建子进程 C 后立即退出，系统把 C 重新托管给其他系统进程，C 继续运行。这个反例能否直接推翻“终止进程时一定终止子进程”？

<details>
<summary>核对</summary>

能。一个合法反例已经足以证明“终止子进程”不是所有操作系统终止父进程时的必然动作。

</details>
