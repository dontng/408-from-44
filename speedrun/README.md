# speedrun｜真题驱动的速通系统

speedrun 不建设教材，也不生产答案口诀。它从用户的真实作答出发，判断当前题真正缺少的机制；按需调用可靠资料，把机制压缩到足以读懂题干、裁决全部选项并接受迁移验证。题目解释完成只表示系统完成了教学，不表示用户已经掌握。

## 唯一完成标准

```text
真实作答
→ 独立诊断问题
→ 建立最小但闭合的机制
→ 裁决全部选项
→ 设计能暴露假懂的验证
→ 在新条件中完成迁移
→ 延迟、混合出现时仍能快速调用
```

本次文档写完时，题目最高只能标为 `explained`。只有用户实际通过验证才能升级：

```text
diagnosed → grounded → explained → verified → transferred → automatic
```

- `diagnosed`：对真实断层提出了可被推翻的判断。
- `grounded`：必要事实和考试口径已经可靠校验。
- `explained`：题干、机制和全部选项已经闭合。
- `verified`：通过专门针对错误理解设计的检验。
- `transferred`：在结构变化后的新题中独立成立。
- `automatic`：延迟、混合出现时仍能快速调用。

不得因为用户说“懂了”、重新选对原题、文档写完或程序跑通，越级标记状态。

## 每批题的执行顺序

1. 读取原题、用户首次作答、参考答案和已有结果；首次作答是证据，永不覆盖。
2. 先在内部独立作答，不拿参考答案反向拼解释。
3. 根据题干和选项建立最小概念关系，判断题目真正要求区分什么。
4. 列出至少两个可能错因，不把某个选项直接等同于用户的心理原因。
5. 按需要校验事实与408口径；只解决当前仍未闭合的问题。
6. 写出最短但完整的机制，使一个原本不了解该点的人能沿关系走到结论。
7. 逐项裁决全部选项，并指出干扰项如何成立或偷换条件。
8. 设计一个最便宜、但足以推翻错误理解的验证。
9. 最后才提炼本批题共同暴露的机制；总结合并重复关系，不替代逐题处理。
10. 进行独立审视。任一质量门槛未通过，重写对应题，不得靠补充段落遮盖断层。

## 从当天结果生成 session

完成答题并生成 `data/results/MMDD.json` 后，在仓库根目录执行：

```bash
./speedrun.sh 0712
```

命令会从真实结果生成 `speedrun/sessions/YYYY-MM/0712.md`，自动写入题号、首次作答、正确答案和逐题固定骨架。新文件使用 `draft`，它不属于掌握状态，也不能作为交付；后继者必须独立完成诊断、最小机制、全部选项裁决和验证设计，再把该题改为 `explained`。

完成正文后执行：

```bash
./speedrun.sh --check 0712
```

检查器会对照不可覆盖的判分结果，验证题目数量与顺序、首次作答、正确答案、状态、四个核心小节和折叠验证答案，并拒绝仍含占位符的文件。它只能挡住结构降级，不能替代对学科内容的独立审视。

## 独立诊断：不复述用户

“用户选了 C”只能证明这次选择是 C，不能直接证明用户为什么选 C。每题先区分：

- 术语完全陌生；
- 单个概念知道，但关系没有建立；
- 机制知道，却没有从题干调用；
- 被选项中的绝对词、时刻、主体或单位误导；
- 只是无把握、猜测或答案污染。

正文写当前证据足以支持的判断。证据不足时写“本题需要建立什么”，不写“你就是哪里不懂”。后续验证负责区分竞争解释。

## 深度控制：问题优先，按需递归

深度由问题触发，不由可访问的资料触发。

```text
能读懂题干？
能裁决全部选项？
能回答紧邻的一个为什么？
能设计最小迁移验证？
```

四项均能则停止。只有某项不能，才向下一层调查。第一性原则不是追溯到历史源头，而是找到足以推出当前结论的最少事实和真实关系。

禁止：

- 从学科史、体系全貌或整章课程开始；
- 为显示专业而展示标准、源码和原稿；
- 把“背景更多”误当成“解释更深”；
- 将单题扩成完整教材；
- 用“篇幅有限”删除决定选项真假的边界。

## 来源策略：可靠但不炫耀

按争议逐级升级：

1. 408 原题、可靠答案与考试口径；
2. 成熟应试资料，用于术语和命题范围；
3. 经典教材的相关小节，用于闭合机制；
4. 标准、RFC、体系结构手册、官方文档或源码，用于裁决冲突与现实边界。

王道或现成课程能够准确、迅速闭合的问题，可以直接采用，不必故意绕远。经典教材和标准是证据库，不是默认授课起点。来源主要在后台校验；只有它实际参与边界裁决时才进入正文或“取证边界”。

## 最小机制：深入浅出

每题的解释必须同时满足：

- **入口浅**：从题干眼前的困难开始，不要求预先学完整章。
- **关系真**：对象、层次、时刻、因果、字段或单位之间的连接准确。
- **范围窄**：只讲当前裁决与邻近迁移必需的内容。
- **能回题**：每段解释最终都能参与题干理解或选项裁决。

优先使用一张紧凑的层次图、时序图、字段图或对照表。图只承载关系，不为装饰；一句话更清楚时不用图。

## 选项裁决：正确项和干扰项同等重要

不能只解释正确答案。每个选项必须明确：

- 它陈述的对象是什么；
- 在什么条件下成立；
- 本题中具体错在哪个词、哪一层、哪个时刻或哪个单位；
- 它是否来自另一个真实但不同的问题。

如果某个错误数值可以由一种合理误算得到，应把误算还原。例如峰值带宽与单次事务平均速率分别对应不同答案；不能笼统称其为“干扰条件”。

## 蒋炎岩式验证：寻找最便宜的反证

验证不问“懂了吗”，也不机械重做原题。先问：

> 如果当前理解是假的，改变什么条件最容易把它击穿？

按问题选择最低成本的检验：

- 术语边界：换表述、换消费主体、重新分类；
- 地址与字段：改变页大小、路数或映射方式；
- 计算：改变决定性变量或改变所问物理量；
- 流水线和协议：推进关键时刻；
- 数据结构：构造空、单元素、重复或极端边界；
- 系统机制：只有纸面无法区分解释时，才写代码、跑模拟或查实现。

验证必须检验机制，不得只替换数字后重复原公式。答案放在折叠区域，验证题放在前面。用户未作答前，状态保持 `explained`。

## 四门课同时生长

speedrun 由题目组织，不按知识章节持续写书；但题单和状态层必须防止碎片化：

- 数据结构：操作过程、边界输入、复杂度与大题实现都要出现；
- 组成原理：字段、时序、数据通路、存储层次和综合题都要出现；
- 操作系统：状态转换、资源管理、并发与存储/I/O 都要出现；
- 计算机网络：分层、报文字段、时序、计算与协议边界都要出现。

每批结束只总结已经由真实题目支撑的共同机制。不得为了覆盖而补写尚未出现的章节；覆盖缺口由后续题单解决。

## 批次质量不得后半程降级

一批有十题，第十题与第一题执行同一标准。禁止出现：

- 前三题有机制与验证，后七题只剩答案；
- 越到后面越依赖“同理可得”；
- 用批次总览替代逐题闭合；
- 因上下文或篇幅紧张压缩必要解释。

如果一次无法保持质量，只能拆成多个文件或多次提交，并保留明确进度；不得交付半批高质量、半批速记式内容。

## 单题固定结构

每题使用 [TEMPLATE.md](TEMPLATE.md)，允许删去不适用的小节，不允许删去以下核心：

1. 首次作答、答案与状态；
2. 真正要解决的问题；
3. 最小机制；
4. 逐项裁决；
5. 最小验证与折叠核对。

## 交付前的否决式审视

逐题回答：

1. 是否把猜测写成了用户错因？
2. 一个零基础读者能否沿现有关系走到答案？
3. 是否有选项只宣布对错、没有裁决依据？
4. 是否为了权威感讲了当前题不需要的内容？
5. 是否为了简短删掉了决定真假的条件？
6. 验证能否击穿一种具体错误理解？
7. 原题重选正确是否被误算成掌握？
8. 本题是否与本批前几题同等认真？

任一答案不合格，本题不得交付。
